# recall

Answer from what this project already knows, before deriving it again.

The description line above is regenerated by `agent-memory compact`. It is the only
part of this system loaded into every conversation, so it stays short on purpose.
Everything below is read only when you actually invoke the skill.

Do the whole job in **one pass**. The routing map and the notes are two terminal
calls inside a single turn. Do not loop, do not re-read, do not ask the user what
they already told a previous window.

---

## Step 1 — Load the routing map (ONE terminal call)

```bash
agent-memory tree
```

`tree` scopes itself to the current repository and always includes globally scoped
notes, because a global constraint applies here too.

Output is one line per note: type, id, title.

```
# memory: orders-api — 12 notes
constraint no-external-db     No externally hosted databases
decision   use-sessions       Chose sessions over JWT
system     auth-service       Auth uses server sessions
```

If the last line reads `N nodes not shown`, that is a real gap, not decoration.
Run `agent-memory tree --all` when the answer plausibly lives in what was dropped.

If the store is empty, say so in one line and answer from the code instead. Do not
invent notes and do not apologize at length.

---

## Step 2 — Choose what to load

Read the titles and decide, **by judgment**, which notes bear on the question. You
are the router. There is no keyword matching underneath this and there should not
be: a title is a sentence, and matching sentences to a question is what you do well
and what a regex does badly.

- Pick 1 to 3 ids. More than 3 means the question is really several questions.
- Always include a `constraint` that touches the subject, even when the user did not
  ask about limits. Constraints are what stop an approach that cannot ship.
- Nothing in the tree looks relevant → go to Step 4.

---

## Step 3 — Load them (ONE terminal call)

```bash
agent-memory get auth-service --depth 1
agent-memory get no-external-db --depth 1
```

`--depth 1` returns the note plus everything one edge away. Use `--depth 2` only
when the question is about how parts fit together rather than about one part.

Two things in the output are load-bearing:

- `[captured N commits ago — verify before trusting]` means the note was written
  against an older state of this repository. Say so when you use it.
- `N nodes omitted for budget` means the neighborhood was larger than the return
  budget. The omitted ids are listed; ask for one directly if it matters.

---

## Step 4 — Fall back to search

Only when the tree had nothing plausible:

```bash
agent-memory search "session revocation"
```

Full text over titles and bodies. If this also misses, the store genuinely does not
know, and saying so plainly is the correct answer.

---

## Step 5 — Answer

Rules that separate a useful recall from a confident wrong one:

1. **Cite the note id** for every claim you take from memory, and the `path:line`
   inside the note when it has one.
2. **Repeat the staleness annotation** if the note carried one. A note captured 47
   commits ago may still be right, but the user decides that, not you.
3. **The code wins.** If a note contradicts what you can read in the repository
   right now, trust the repository, say which note is wrong, and suggest
   `/remember` to correct it. A store that quietly rots is worse than no store.
4. **Never present an `inferred` note as established.** The note says which it is.
5. Answer the question. Do not summarize the store.

---

## Failure handling

- **`agent-memory: command not found`.** The package is not installed or not on
  PATH. Say so and answer from the code; do not attempt to install it.
- **Empty store.** Answer from the code, then mention `/remember` once.
- **`doctor` reports a problem.** Report it in one line and continue. `index.db` is
  a cache; `agent-memory index` rebuilds it from the markdown, which is the source
  of truth and is never lost.
